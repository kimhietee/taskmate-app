Recruit independent student and local employer participants (excluding project group members and family contacts) and use strictly synthetic test accounts and synthetic task scenarios.

## Representative tasks

### Student

1. Register as a student, locate the verification state, and identify what is needed next.
2. Open an approved task on a mobile or desktop browser and locate all six upfront offer terms (**Tasks**, **Hours**, **Pay amount**, **When paid / Pay timing**, **Location**, and **Contact**), noting any field marked **To be discussed**.
3. Read a task with **Bi-weekly** pay timing beside the pay amount and state both the amount and when payment arrives.
4. Enter a sample weekly class schedule once in **My classes**, save it, and compare it against (a) a fitting weekend offer, (b) a fixed-shift weekday clash, and (c) an offer whose hours are **To be discussed**.
5. Run the **3-item pre-acceptance checklist** in **The poster**, use **Ask poster** to draft a question about missing/clashing terms, open **Check before you apply**, go back to edit, and then submit an application.
6. Review a proposed two-party agreement, identify the payment-boundary notice, confirm or request changes, and locate where completion, payment status, rating, and reporting live.

### Poster / Employer

1. Register as a faculty/staff or organization representative and identify the approval state.
2. Create a task listing tasks, work hours (or **To be discussed** + **Can hours change?**), pay amount (or **To be discussed**), pay timing, work mode, and workplace information when applicable.
3. Review an applicant, answer missing-term questions in private chat, and propose a two-party agreement settling the final amount, work hours, and payment timing before work starts.
4. Record completion and payment status and locate the report workflow.

## System Usability Scale (SUS)

Ask agreement on a 1 to 5 scale (1 = strongly disagree, 5 = strongly agree):

1. I think that I would like to use this system frequently.
2. I found the system unnecessarily complex.
3. I thought the system was easy to use.
4. I think that I would need the support of a technical person to be able to use this system.
5. I found the various functions in this system were well integrated.
6. I thought there was too much inconsistency in this system.
7. I would imagine that most people would learn to use this system very quickly.
8. I found the system very cumbersome to use.
9. I felt very confident using the system.
10. I needed to learn a lot of things before I could get going with this system.

Scoring: for odd-numbered items subtract 1 from the response; for even-numbered items subtract the response from 5; sum the adjusted values and multiply by 2.5. Report only anonymous responses through the separately approved research process described in `docs/research-data-separation.md`.
